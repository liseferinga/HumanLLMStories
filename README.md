# Human vs. LLM Dutch Short Stories
### Master's Thesis | Digital Humanities

## About

This repository contains all data and code for a thesis investigating whether Dutch short stories generated by GenAI are comparable to human-written stories in terms of creativity.

> **Research question:** To what extent are Dutch short stories generated by prompting GenAI comparable to those written by human authors in terms of creativity?

Creativity is operationalized using the [Torrance Test of Creative Writing](https://arxiv.org/pdf/2309.14556) (Chakrabarty et al., 2024), evaluated through three pipelines: human raters, LLM raters, and computational text analysis.

## The TTCW framework

The 14 TTCW criteria are grouped into four dimensions:

| | Dimension | Criteria |
|---|---|---|
| 🩵 | **Fluency** | Narrative pacing · Scene vs. exposition · Literary devices · Narrative ending · Understandability & coherence |
| 💚 | **Flexibility** | Perspective & voice flexibility · Emotional flexibility · Structural flexibility |
| ❤️ | **Originality** | Theme & content · Originality in thought · Originality in form & structure |
| 🤎 | **Elaboration** | World building & setting · Character development · Rhetorical complexity |

## Dataset

Stories are fetched automatically from [`liseferinga/HumanLLMStories`](https://github.com/liseferinga/HumanLLMStories) via the GitHub API. The corpus contains **36 prompts × 4–5 sources** (human, Claude, GPT-4o, GPT-5.5, Gemini) of Dutch short fiction.

## Notebooks

### 1 · Computational pipeline — `ComputationalCreativityAssessment.ipynb`

Implements all 14 TTCW criteria using NLP methods. For each criterion the pipeline: computes metrics per story → aggregates by source (median) → runs statistical tests (Shapiro–Wilk, Kruskal–Wallis, Mann–Whitney U with Cliff's δ, paired Wilcoxon for GPT-4o vs. GPT-5.5)

Medians are used throughout instead of means because the data is not normally distributed (confirmed per Shapiro–Wilk). Bonferroni correction is applied within each TTCW's GPT version comparison separately.

#### What each TTCW measures computationally

| # | Criterion | Method |
|---|---|---|
| 1 | Narrative pacing | Event span extraction via `nl_core_news_lg` finite verb detection; event-type classification (non-event / stative / process / change-of-state, narrativity 0–7); peak detection + Shannon entropy |
| 2 | Scene vs. exposition | Action ratio, dialogue ratio, concreteness ratio (reuses TTCW 1 labels); temporal uniformity of narrativity scores; composite scene score |
| 3 | Literary devices | Metaphor score via cosine distance of adj–noun, verb–subject, verb–object pairs (`nl_core_news_lg`); simile density via Dutch comparative markers |
| 4 | Narrative ending | Sentiment consonance using RobBERT embeddings; narrativity consonance using TTCW 1 event labels; local dissonance and trajectory break scores across story segments (25 / 50 / 25%) |
| 5 | Understandability & coherence | Entity persistence from `dutchcoref` CoNLL output; embedding similarity via RobBERT consecutive sentence cosine similarity; entity grid visualization with Alpino XML grammatical roles |
| 6 | Perspective & voice flexibility | Private-state verb detection; subjectivity ratio; POV trigger classification (continuation / resumption / initiation) |
| 7 | Emotional flexibility | Interior vs. exterior balance; epistemic modal markers; past perfect memory markers |
| 8 | Structural flexibility | Surprise variance and peak position via `paraphrase-multilingual-mpnet-base-v2` consecutive sentence embeddings; mean appropriateness score |
| 9 | Theme & content | Corpus deviation and prompt deviation using mean story embedding vs. corpus/prompt centroid |
| 10 | Originality in thought | Cliché detection via lemma matching against a Dutch cliché lexicon |
| 11 | Originality in form & structure | Punctuation density, adverb density, sentence length variance, POS trigram entropy (`nl_core_news_lg`) |
| 12 | World building & setting | Sensory density and breadth from Speed & Brysbaert (2022) Dutch norms; spatial anchor detection via NER |
| 13 | Character development | Narrative space (sentence presence proportion); emotional valence variability from Moors et al. (2013) norms; character co-occurrence network centrality |
| 14 | Rhetorical complexity | Cultural entity count; thematic deviation via THEMATIC_DICTIONARY motif matching (Bamman et al., 2019 pipeline) |

### 2 · Human rater pipeline — `humanresults.ipynb`

Processes Qualtrics survey data from the human judgement study. Each rater evaluated one pair of Dutch stories (one human-written, one LLM-written, same prompt with order counterbalanced) using the 14-item TTCW binary checklist (Ja/Nee). Raters then guessed which story was AI-written.

#### Study design

- Each rater saw **one story pair** only (one human + one LLM story matched by prompt)
- Presentation order (`llm_first` / `human_first`) was randomized
- Author (human or LLM) identity was not disclosed
- Each rater evaluated exactly one LLM model (Claude, GPT, or Gemini). The LLM model is therefore confounded with the rater, which the GLMMs handle via random effects
- Final sample: **113 respondents** (33 expert, 80 non-expert) after exclusions

#### Completion status coding

| Code | Meaning |
|---|---|
| 0 | No story ratings completed |
| 1 | Only one story rated |
| 2 | Both stories rated, no attribution attempt |
| 3 | Fully complete ← enters main analysis (Dataset B) |

#### Prerequisites

```bash
pip install pandas numpy scipy scikit-learn matplotlib krippendorff statsmodels
```

**R is required** for the inferential statistics section. R scripts are written and executed via `subprocess`. Install R and ensure `Rscript` is on your PATH. R packages (`lme4`, `performance`, `DHARMa`, `broom.mixed`, `emmeans`) are installed automatically by the scripts if missing.

#### Files that must be supplied manually

| File | Description |
|---|---|
| Raw Qualtrics export `.csv` | The survey export. Qualtrics adds two metadata rows at the top — the notebook skips rows 1 and 2 automatically on load. Set the path at the top of the notebook. |
| `expertise_lookup.csv` | Semicolon-delimited file with columns `ResponseId` and `expertise` (`expert` / `non-expert`). Coded externally from field-of-study responses — not derivable from the survey data alone. |

**Known data issue:** Three responses are missing the `llm_model` field from Qualtrics. These are patched via the `MANUAL_LLM_MODEL` dict, confirmed against source records. This is intentional and reproducible.

#### What the pipeline produces

1. Cleaned dataset with subscale scores (Fluency, Flexibility, Originality, Elaboration, 0–14 total)
2. Quality-control flags: straightliner detection (all-Ja or all-Nee across all 28 items), completion filtering
3. Long-format `model_data.csv`: one row per rater × story × TTCW item, for the GLMM
4. Descriptive tables: TTCW scores by expertise and LLM model; Krippendorff's α per item; Cohen's κ between expert and non-expert consensus; pass rates per item by source/model/expertise
5. Attribution accuracy (did raters correctly identify the AI story?) by expertise group and LLM model
6. Four R-based binomial GLMMs: binary LLM vs. human, author × expertise interaction, source × question interaction, expertise × question interaction, attribution accuracy model
7. Visualizations: score distributions, GLMM forest plots, per-item pass rate charts, PCA/k-means rater clustering

### 3 · LLM-as-assessor pipeline — `LLM.ipynb`

Processes the results of using Claude, GPT, and Gemini as automated creativity judges applying the same 14-item TTCW checklist. Each item is a separate API call to ensuure no within-judge memory or repeated-measures structure. The notebook computes scores, measures inter-rater reliability between the three LLM judges, compares LLM judge ratings to human rater ratings, fits a GLMM, and checks for self-preference bias.

> **Run the human pipeline first.** This notebook reads `model_data.csv` and `outputs/dataset_B_final.csv` produced there.

#### Prerequisites

```bash
pip install pandas numpy scipy scikit-learn statsmodels matplotlib
```

**R is required** for two scripts: `analysis_llm_irr.R` (ICC via `psych`) and `analysis_llm_glmm.R` (`lme4`, `blme`, `performance`, `broom.mixed`). Both install their own packages automatically; R itself must be on your PATH.

#### Files that must be supplied manually

| File | Description |
|---|---|
| `llm_assessor_results.csv` | Raw output from the LLM API assessment run (separate upstream step, not part of this notebook) |
| `llm_attribution_results.csv` | Results from the LLM attribution task (each judge guessed which story was AI-written) |

#### Known quirks

- **Fluency1 and Fluency3** have a higher rate of parsing gaps than other items and are flagged separately in the exclusion logic — this asymmetry is intentional.
- **API errors** are flagged and excluded. The exclusion log is printed during cleaning for reproducibility verification.
- Three GLMM terms (GPT-as-author rated by GPT or Claude; items Flexibility1, Originality2, Elaboration2) show near-complete separation. This is why `blme` is used instead of plain `lme4`.

#### GLMM design note

Unlike the human pipeline, there is **no rater-level random effect** because each API call is independent, `(1 | set)` is the only random effect. Fixed effects: source (Human/LLM), author (Claude/GPT/Gemini), judge (Claude/GPT/Gemini), question ID (1–14), `score_diff_z` (covariate).

#### What the pipeline produces

1. `llm_assessor_clean.csv` — cleaned item-level ratings
2. `llm_irr_wide.csv` and `icc_summary.csv` — ICC results for inter-judge reliability on human stories
3. `llm_glmm_data.csv` and six CSV outputs from the GLMM
4. Descriptive tables: pass rates by author, judge, item; attribution accuracy by judge with binomial tests against chance (50%); Pearson/Spearman correlations and Cohen's κ comparing LLM judges to human raters
5. Self-preference bias check: raw pass rates by category (own writing / other LLM / human) per judge — computed on raw data rather than GLMM coefficients, because the author × judge interaction terms are the ones most affected by separation
6. Visualizations: GLMM forest plots, pass rate charts, attribution accuracy comparison between human and LLM judges — all saved as `.png`
